# Use Pair-scoped read grants instead of shared Task ownership

Duit will model exactly two independently owned Task systems connected by an exclusive Pair, not a shared workspace. Every Task has one immutable Owner and Task-wide Visibility backed by either no grant or `Shared(pairId, shareGeneration)`; a Partner may read only a redacted Shared View and may never mutate canonical Task state. The Shared View is a derived offline-batched projection containing current definition/schedule data, Subtask labels, and date-level positive completions from the current prospective Share Grant. Reminders, Focus, checked Subtask progress, negative outcomes, exact action times/zones, corrections, and diagnostics remain Owner-only. New Tasks default to Shared only while paired, pre-pair Tasks remain Private until explicitly shared, and a new Pair or re-share creates a new generation that never inherits old access or Cheers. This deliberately accepts a small denormalized read model to avoid both collaborative ownership and surveillance-level disclosure. Server revocation cannot retract viewed information or securely erase an offline cache, so the product discloses that limit honestly.
