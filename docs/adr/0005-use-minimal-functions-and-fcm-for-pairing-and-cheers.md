# Use minimal Cloud Functions and FCM for Pairing and Cheers

**Status:** Partially superseded by [ADR-0006](0006-approve-members-individually-and-keep-pairing-optional.md).

Duit will add narrowly scoped Cloud Functions 2nd gen for server-authoritative Pair Invite creation/mutual confirmation, Unpairing, and idempotent FCM fan-out after a Cheer synchronizes. Ordinary Task creation, editing, completion, recurrence, reminders, Shared View projection, and synchronization remain direct offline-capable Firestore operations; there is no general application API. Deterministic per-UID membership locks make exactly-two Pair activation atomic, while server-only invite-rate and Cheer-delivery ledgers prevent replay, in-memory rate-limit gaps, recursive triggers, and notification spam. The trusted boundary is justified because membership changes require an online atomic decision and background delivery requires a server-held FCM sender credential. Firestore remains the source of Cheer truth; FCM is best effort, contains no Task content, checks the recipient UID on-device, and sends at most once per eligible target in a rolling 24-hour window. Production Functions require Blaze billing, and all functions enforce Auth, App Check, the two-UID allowlist, active Pair/Share Grant, and target validity.
